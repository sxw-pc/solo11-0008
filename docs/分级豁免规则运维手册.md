# 分级豁免规则复核模块运维手册

本模块面向跨安全域数据交换中「经多部门确认可接受的历史遗留问题」，在不破坏
默认严格拦截的前提下，提供可配置、可审计、可追溯的分级豁免能力。模块完全本地
离线运行，不发起任何网络请求。

## 一、设计原则与安全边界

1. **默认严格拦截**：未命中规则、规则过期、规则停用、规则文件非法或模块内部
   异常，异常项一律保持拦截，绝不产生未授权豁免放行。
2. **高危异常不可豁免**：路径穿越（`path_traversal`）、压缩炸弹（`zip_bomb`）、
   高危可执行文件（`dangerous_file`）、整包哈希不符（`package_hash_mismatch`）
   即使存在通配豁免规则也永不放行。
3. **快照隔离**：每个任务在启动时一次性加载不可变规则快照，任务运行期间规则
   文件的任何增删改都不影响该任务的最终结论；多任务并行互不干扰。
4. **资源自动释放**：引擎持有的规则实例在任务结束（含异常路径）后自动释放，
   弱引用登记表保证无内存泄漏。
5. **审计不可篡改**：每个任务生成独立的只追加 JSONL 审计文件，记录之间以
   `prev_hash` 串联并对内容做 SHA256 哈希，任何篡改、删除、乱序均可被
   `verify_audit_chain` 检出；文件权限收紧为仅属主可读写。
6. **向后兼容**：未配置豁免规则时模块整体短路，原有校验流程的过程与结果与
   旧版本完全一致；历史任务无豁免字段时读取不报错，默认全部异常为拦截状态。

## 二、规则文件配置

规则只允许从本地 YAML 加载，在 `AppConfig(exemption_rules_path=...)` 或配置
YAML 中指定。文件不存在或未配置表示不启用豁免。完整样例见
`fixtures/mock_exemption/exemption_rules.example.yaml`。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 规则唯一标识，仅允许字母数字、`-`、`_`，不可重复；豁免记录据此关联 |
| `business_domain` | 是 | 适用业务域；`*` 为任意域。数据包业务域取自 `manifest.packet.business_domain`（兼容顶层 `business_domain`） |
| `anomaly_types` | 是 | 异常类型代码列表，`*` 表示任意类型 |
| `scope.tables` | 否 | 影响范围：表名列表，支持 `*`；省略表示不限 |
| `scope.fields` | 否 | 影响范围：字段名列表，支持 `*` |
| `scope.paths` | 否 | 影响范围：文件路径列表，支持 `*` |
| `action` | 是 | `exempt` 豁免放行，或 `deny` 显式拒绝（维持拦截） |
| `grade` | 是 | 豁免分级 `L1`（临时）/`L2`（限期）/`L3`（长期备案） |
| `effective_from` / `effective_to` | 是 | 有效期闭区间，支持 `YYYY-MM-DD` 或带时间格式 |
| `approvers` | 是 | 至少一个确认部门，不允许通配符 |
| `reason` | 否 | 历史遗留问题与放行依据 |
| `enabled` | 否 | 默认 `true`；`false` 时规则不参与匹配 |

无业务域的历史数据包，仅 `business_domain: "*"` 的规则可能命中，具体业务域
规则不会越权匹配无域数据。

## 三、冲突仲裁（最严格优先级）

同一异常命中多条规则时，按以下确定性顺序选择唯一生效规则，并在报告与审计中
输出冲突提示及全部候选规则 ID：

1. `deny` 始终优先于 `exempt`；
2. 动作相同，匹配维度越具体（业务域 > 异常类型 > 表 > 字段 > 路径）优先级越高；
3. 具体度相同，有效期更早到期者优先；
4. 仍相同则按规则 ID 字典序兜底，保证结果可复现。

## 四、审计留痕与校验

审计文件位于工作目录 `exemption_audit/<任务ID>.audit.jsonl`，每行一条记录，
事件类型包括 `chain_open`、`decision`、`default_block`、`expired_block`、
`chain_close`。记录含任务 ID、规则快照指纹、异常定位、命中规则完整内容、
候选规则、冲突标记、有效期与链式哈希。

完整性校验：

```python
from gateway.exemption import verify_audit_chain
result = verify_audit_chain("workspace/exemption_audit/<task_id>.audit.jsonl")
assert result["valid"], result["error"]
```

任务历史（SQLite `result_json.exemption`）与三种格式报告（Markdown/HTML/JSON）
均同步包含豁免汇总、逐条豁免记录（规则 ID、分级、有效期）、冲突提示与审计
文件相对路径，可随报告整体归档迁移。

## 五、与校验项的对应关系

| 校验项 key | 豁免最小单元 | 典型异常代码 |
| --- | --- | --- |
| `hash` | 每条文件级错误 | `redundant_file`、`hash_mismatch` 等（`dangerous_file` 禁免） |
| `schema` | 表级每条字段错误 | `type`、`required`、`enum`、`maxLength` 等 |
| `lineage` | 每条关联的每个错误 | `orphan_record`、`cardinality_error` 等 |
| `anomaly` | 字段 × 失败规则 | `null_rate`、`duplicate_rate`、`range` 等 |

`archive`（压缩包安全）、`table_read`、`internal` 等校验项不参与豁免。

## 六、运维注意

- 规则变更后只对**新启动**的任务生效，在跑任务沿用启动时快照。
- 规则文件 YAML 损坏或字段非法时，任务不会中断，但会禁用全部豁免并在任务
  日志中记录原因，回退到严格拦截。
- 审计文件为只追加设计，禁止手工编辑；如需作废豁免，应停用或修改规则后让
  新任务自然拦截，而非改动历史审计记录。
