# 契约配置手册

本手册说明数据包 `manifest.yaml`、数据契约 YAML 与异常规则 YAML 的写法。示例均可对照 `fixtures/mock_contract/` 与 `fixtures/mock_lineage/`。

## 一、文件分工

| 文件 | 位置 | 作用 |
| --- | --- | --- |
| `manifest.yaml` | 数据包根目录 | 声明包信息、逻辑表到文件路径的映射、逐文件哈希 |
| 数据契约 YAML | 由页面选择或上传 | 声明表字段、类型、约束与异常抽检规则 |
| 血缘规则 YAML | 由页面选择或上传 | 声明跨表关联、基数与引用要求 |

三份文件均使用 UTF-8 编码和 YAML 映射结构。契约超过 2 MiB、manifest 超过 1 MiB 会被视为异常。

## 二、manifest.yaml

```yaml
schema_version: "1.0"
packet:
  name: retail_valid_1
  created_at: "2026-01-01T00:00:00"
  description: 虚构离线样例
tables:
  users:
    path: data/users.csv
    format: csv
  products:
    path: data/products.parquet
    format: parquet
  orders:
    path: data/orders.sqlite
    format: sqlite
    table: orders
files:
  data/users.csv:
    md5: 32位十六进制摘要
    sha256: 64位十六进制摘要
  data/products.parquet:
    sha256: 64位十六进制摘要
```

要点：

1. 文件必须位于压缩包根目录；若外层多套一层目录，会报“缺少 manifest.yaml”。
2. `tables` 的键是逻辑表名，必须与契约、血缘中的表名一致。
3. `path` 使用压缩包内相对路径；不得包含 `..`、盘符或前导 `/`。
4. csv/parquet 可省略 `format`，按扩展名推断；sqlite 必须提供 `table`。
5. `files` 中声明的文件必须存在，包内未声明的非白名单文件会被判为冗余。声明路径会做 POSIX 归一化：`./data/a.csv`、`data//a.csv`、`data/./a.csv` 视为同一路径，且匹配时大小写不敏感；两种写法归一化后指向同一文件会报重复声明。
6. 哈希字段可提供 `md5`、`sha256` 或两者；缺失的算法不会参与核验。仅提供 `md5` 的旧版 manifest 继续兼容。

## 三、数据契约结构

```yaml
version: "1.0"
name: user_trade_contract
description: 交易域样例契约
allow_extra_fields: false
tables:
  users:
    file: data/users.csv          # 仅作说明，实际路径以 manifest 为准
    allow_extra_fields: false
    aliases:
      user_name: [userName, name]
    fields:
      user_id:
        type: string
        required: true
        nullable: false
        pattern: '^U[0-9]{4}$'
        maxLength: 8
```

### 3.1 表级选项

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `file` | 字符串 | 说明性字段，不参与路径解析 |
| `allow_extra_fields` | 布尔 | 是否允许包里出现契约未声明字段，缺省继承契约根级设置 |
| `aliases` | 映射 | 标准字段名到上游候选列名的映射 |
| `fields` | 映射 | 必填，字段级规则 |

### 3.2 字段级规则

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `type` | string/integer/number/boolean/array/object | 也接受 int、float、bool 简写 |
| `required` | 布尔 | 列必须存在；`required: true` 且 `nullable` 未写时默认不可空 |
| `nullable` | 布尔 | 是否允许空值；显式设置优先 |
| `enum` | 列表 | 取值必须属于列表 |
| `minimum` / `maximum` | 数值 | 数值边界，包含端点 |
| `pattern` | 正则字符串 | 使用 Python 正则匹配 |
| `minLength` / `maxLength` | 整数 | 字符串长度限制 |
| `format` | JSON Schema 格式 | 常用 `date`、`date-time`、`email`、`uri` |

类型转换规则：pandas 标量先转换为 Python 标量；整数列允许整数值，浮点列允许数值；日期对象转为 ISO 字符串后交给格式检查器。空字符串按空值处理。

### 3.3 别名映射

```yaml
aliases:
  user_name: [userName, name]
```

- 只有标准字段不存在时才尝试别名。
- 多个别名同时命中，或标准字段与别名同时存在，记为 `alias_conflict`。
- 别名只做列重命名，不改变字段类型。
- 异常抽检规则按规范字段书写即可，命中唯一别名时会自动解析到对应物理列；多个别名同时命中则按字段缺失处理，由 Schema 阶段的 `alias_conflict` 拦截。

### 3.4 多余字段

契约根级 `allow_extra_fields: false` 时，表级未单独设置的将继承该值；表级配置优先。多余字段会生成字段级错误，但不会阻止其余字段继续校验。

## 四、异常规则

异常规则位于契约根级 `anomaly_rules`，结构为“表 → 字段 → 规则列表”。表或字段不存在会生成 `table_missing` / `field_missing` 配置错误。

```yaml
anomaly_rules:
  trades:
    trade_id:
      - rule: duplicate_rate
        max: 0.0
    amount:
      - rule: range
        min: 0
        max: 100000
        max_rate: 0.0
    trade_date:
      - rule: date
        format: "%Y-%m-%d"
```

### 4.1 range

必填 `min` 或 `max` 至少一个。非空、无法转为数值的值直接判为异常；空值跳过。`max_rate` 为允许异常占比，缺省 0。

### 4.2 regex

必填 `pattern`。`full_match: true` 时整串匹配，否则执行搜索。空值跳过。

### 4.3 date

`format` 指定 `datetime.strptime` 格式；也可用 `formats` 列表尝试多种格式。pandas 的时间戳/日期对象直接视为合法。

### 4.4 null_rate

`max` 为允许的最大空值率（0 到 1）。统计范围包含全部抽样行，空白字符串计为空。

### 4.5 duplicate_rate

`max` 为允许的最大重复值占比。空值不参与重复统计，重复率按“重复出现的行数 / 非空行数”计算。

### 4.6 custom

```yaml
anomaly_rules:
  trades:
    amount:
      - rule: custom
        function: no_negative
        max_rate: 0.0
```

函数必须登记在 `gateway/validator/custom_rules.py` 的 `CUSTOM_RULES` 中，当前提供：

| 名称 | 判定 |
| --- | --- |
| `no_negative` | 非空值必须能转数值且不小于 0 |
| `non_empty` | 非空字符串去除空白后不得为空 |

返回值必须是与输入同索引的布尔序列，True 表示异常。系统不会加载上传的 Python 代码；新增函数须由开发人员修改代码并重新测试。

## 五、校验与失败定位

Schema 结果包含表、字段、行号、错误码与截断后的原值。常见错误码：

| 错误码 | 含义 |
| --- | --- |
| `table_missing` | manifest 或数据中缺少契约表 |
| `field_missing` | 契约字段不在表中 |
| `unexpected_field` | 表中存在未声明字段且不允许 |
| `alias_conflict` | 标准字段与别名冲突或多个别名同时命中 |
| `type` / `enum` / `pattern` / `format` | 对应 JSON Schema 约束失败 |
| `required` | 必填字段缺失或值为空 |

异常抽检结果按字段保留规则级明细，并在全局样例中保留最多 20 条。报告中的行号是原始数据行号（含表头偏移）。

## 六、编写建议

1. 先保证 manifest 与契约表名一致，再调试字段规则。
2. 对可变字段尽量使用 `enum` 或边界，不要写过度宽泛的类型。
3. 异常规则阈值与契约约束相互独立：类型/必填问题在 Schema 阶段拦截，统计型问题在抽检阶段拦截。
4. 自定义契约上传后在任务报告中会记录配置指纹，便于追溯。
5. 修改契约后先运行 `test.sh`，确认内置样例仍然通过。
