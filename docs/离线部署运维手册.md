# 离线部署运维手册

本手册面向内网离线环境，说明依赖准备、部署、启动、目录规划、数据保留、备份、安全加固与故障排查。工具不依赖云服务、外部 API、CDN、外部数据库或消息队列。

## 一、部署前提

- Python 3.9、3.10 或 3.11，64 位。
- 可写工作目录，默认项目下 `workspace/`。
- 可用磁盘应大于单次最大上传包与解压总量之和；默认上限 1.5 GiB 上传、10 GiB 解压。
- 服务仅监听回环地址，禁止改为对外网卡；远程使用请通过受控远程桌面或堡垒机访问本机浏览器。

## 二、离线依赖准备

在联网机器上准备**与目标机相同 Python 版本、相同操作系统架构**的 wheel：

```bash
python -m pip download -r requirements.txt -d vendor/wheels
```

固定版本为 Flask、Werkzeug、Jinja2、pandas、numpy、PyYAML、jsonschema、python-magic、pyarrow、pytest、pytest-cov。pandas 1.5.3 需要 NumPy 1.x，因此 requirements 显式固定 `numpy==1.24.4`，避免新版本 ABI 不兼容。

把项目与 `vendor/wheels` 复制到离线机，然后：

```bash
python -m venv .venv
# Windows
.venv\Scripts\python -m pip install --no-index --find-links vendor/wheels -r requirements.txt
# Linux / macOS
.venv/bin/python -m pip install --no-index --find-links vendor/wheels -r requirements.txt
```

Windows 若没有 libmagic，`python-magic` 不可用属于预期情况；应用自动使用安全默认 MIME，不阻塞校验。

## 三、启动与停止

```bash
# Linux / macOS
PYTHON=.venv/bin/python ./run.sh
# Windows
set PYTHON=.venv\Scripts\python.exe
run.bat
```

前台运行，`Ctrl+C` 停止。启动日志会打印访问地址，默认 `http://127.0.0.1:5000`。

指定独立数据目录：

```bash
GATEWAY_WORKSPACE=/srv/gateway-data PYTHON=.venv/bin/python ./run.sh
```

工作目录必须由运行账号独占写入；不要放在共享目录或可被其他用户改写的路径。

## 四、目录与数据

```text
workspace/
  gateway.db          SQLite 任务历史
  uploads/            预留上传目录
  tmp/                上传副本与解压临时目录
  reports/            <task_id>.md/.html/.json
  logs/               <task_id>.log
```

- 上传文件保存在 `tmp/upload-*`，请求结束自动删除。
- 解压目录为 `tmp/gateway-*`，任务结束或异常自动删除。
- `reports/`、`logs/`、`gateway.db` 长期保留，由人工按保留策略清理。
- 报告与日志路径保存在数据库相对路径中；手工移动文件会导致下载 404。

### 4.1 数据库结构

`tasks` 表保存任务 ID、包名、大小、整包 SHA256、压缩类型、上传/完成时间、状态、是否通过、契约名、血缘名、耗时、配置指纹、工具版本、错误摘要、三类报告路径、日志路径与完整结果 JSON。常用索引为上传时间和状态。

### 4.2 报告内容

- Markdown：便于文本归档与工单流转。
- HTML：内联样式单文件，无外部脚本、字体、图片和 CDN，可脱机打开。
- JSON：结构化结果，适合后续抽取或二次审计。

报告记录工具版本、配置指纹、环境信息、六类校验结果、异常样例与修复建议。HTML 报告中的 Mermaid 为源代码，不加载外部渲染库。

## 五、运行账号与权限

建议创建专用低权限账号，仅授予工作目录读写权限。不要使用 root/Administrator 运行。禁止把工作目录设为 Web 根目录或共享给不受信用户。

服务没有登录、RBAC 与多租户能力，这是刻意的安全边界：只允许本机回环访问，不要通过反向代理暴露到网络。

## 六、数据保留与清理

建议按组织要求定期清理已完成任务。优先使用页面“删除任务”，它会同时删除报告、日志和数据库记录。

手工清理顺序：

1. 先备份 `gateway.db`。
2. 根据数据库中的 `report_md`、`report_html`、`report_json`、`log_path` 定位文件。
3. 删除文件后再删除数据库记录，避免残留指向。
4. 清理 `tmp/` 下异常退出遗留的 `upload-*`、`gateway-*` 目录；确认没有正在运行的任务。

保留策略示例：通过任务保留 90 天，失败任务保留 180 天，报告与日志同步。具体周期由组织审计要求决定。

## 七、备份与恢复

备份：

```bash
# 停止服务后执行，确保数据库一致
cp -a workspace /backup/gateway-workspace-YYYYMMDD
```

Windows 可停止进程后复制整个 `workspace`。恢复：停止服务，替换整个工作目录，确认权限与磁盘空间，再启动服务。

不要只备份 `gateway.db` 而忽略报告与日志；恢复后页面记录存在但文件缺失会导致下载失败。

## 八、升级

1. 停止服务并备份工作目录。
2. 保留原 `workspace`，替换代码与依赖。
3. 用同一工作目录启动；数据库表使用 `CREATE TABLE IF NOT EXISTS`，可直接沿用。
4. 运行 `test.sh` 或 `test.bat` 确认环境。
5. 验证首页、历史任务、报告下载与删除。

升级不自动迁移历史结果字段；旧任务的 `result_json` 仍按原结构展示。

## 九、安全检查清单

- [ ] `host` 仍为 `127.0.0.1`、`localhost` 或 `::1`。
- [ ] 运行账号为专用低权限账号。
- [ ] 工作目录不在共享盘，权限最小化。
- [ ] 上传上限、解压上限、条目数与压缩比阈值符合业务包规模。
- [ ] `blocked_extensions` 未被随意删减。
- [ ] 防火墙禁止外部访问 5000 端口。
- [ ] 定期备份并按保留策略清理报告、日志与数据库。
- [ ] 自定义异常规则只由开发人员修改白名单，不接受上传代码。
- [ ] 抽查 HTML 报告无外部资源引用。

## 十、故障排查

| 现象 | 排查 |
| --- | --- |
| 启动失败“仅允许监听本机回环地址” | 将 host 改回 127.0.0.1/localhost/::1 |
| 端口占用 | 修改配置端口，或停止占用进程 |
| 上传 413 | 包体超过 `max_content_length`，确认业务是否应拆分 |
| 包被判定 Zip 炸弹 | 查看日志中的条目名与压缩比；确认是否为正常高压缩数据 |
| 缺少 manifest.yaml | 清单必须在根目录，不能多套一层目录 |
| 表读取失败 | 检查 manifest 路径、格式、sqlite 表名、文件是否损坏 |
| 契约加载失败 | 检查 YAML 根节点、tables/fields 映射、字段 type |
| 血缘大量孤立 | 检查表名字段名、左右端点方向、键格式与前导零 |
| 报告下载 404 | 报告被手工移动或删除；重新校验并保留文件 |
| 删除任务失败 | 关闭占用报告文件的程序；必要时停止服务后手工清理 |
| 中文乱码 | 上游统一 UTF-8；读取器会尝试 GBK 兜底 |
| 测试覆盖率不足 | 确认使用 `test.sh`/`test.bat`，不要跳过测试文件 |

查看任务日志：页面任务详情底部显示末尾 120 行；也可直接查看 `workspace/logs/<task_id>.log`。

## 十一、性能与容量

异常抽检默认 10%，随机种子 42，结果可复现；血缘校验使用全量数据。`random_seed` 必须配置为整数（缺省 42），配置为 null 或非整数会在启动时直接报错，避免抽样回退到全局随机源导致同一数据包多次结果不一致；SQLite 表读取使用显式 `ORDER BY` 固定行序，保证抽样行号与 Top20 样例跨运行、跨重建稳定。空值率与重复率均以抽样行按统一口径计算（空白字符串计为空，空值不参与重复统计）。大包的主要耗时在解压、哈希和 parquet/sqlite 读取。容量规划以“上传包 + 解压后总量 + 报告”估算，并预留 20% 余量。

单进程多线程适合本机单用户或少量并发。工具不提供分布式调度；高并发场景应由组织另行设计队列与隔离，而不是修改回环监听边界。
